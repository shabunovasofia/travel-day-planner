# Planner-service: описание работ участника 2

Сервис `planner-service` отвечает за построение плана прогулочного дня: принимает временной интервал и список мест, рассчитывает длительность посещений, подбирает порядок обхода, формирует расписание и предупреждения. Стек соответствует требованиям лабораторных работ: Java 17, Spring Boot, REST API, JUnit, Docker.

## Лабораторная работа 1

Задача участника 2: описание модели достопримечательностей и активностей, заготовка REST API.

Реализовано:

- DTO `PlaceDto`: модель достопримечательности с `placeId`, названием, категорией, координатами, оценочной длительностью, описанием и рейтингом.
- DTO `PlanRequest`: входные данные для построения плана.
- DTO `PlanResponse` и `PlanItem`: результат планирования и отдельные элементы расписания.
- REST API:
  - `POST /api/v1/plan/build` - построение плана;
  - `GET /api/v1/plan/health` - проверка доступности сервиса.
- Обработка ошибок в `PlannerExceptionHandler`: некорректные входные данные возвращают HTTP 400 с JSON-полем `error`.

## Лабораторная работа 2

Задача участника 2: реализация алгоритма подбора и ранжирования маршрутов, расчёт длительности активностей, подсчёт вариантов.

Реализовано в `RoutePlanning`:

- Расчёт длительности активности: `estimatedVisitMinutes(PlaceDto)` переводит `estimatedHours` в минуты.
- Последовательное построение расписания от `startTime` до `endTime`.
- Пропуск активностей с некорректной длительностью и добавление предупреждений.
- Пропуск мест, которые не помещаются в доступный интервал дня.
- Подбор порядка посещения:
  - для списков до 7 мест включительно перебираются все перестановки;
  - лучший вариант выбирается по максимальному числу запланированных мест, затем по сумме рейтингов;
  - для списков больше 7 мест используется жадное ранжирование: рейтинг по убыванию, длительность по возрастанию, затем `placeId`.
- Подсчёт проверенных вариантов возвращается в ответе API в поле `evaluatedOrderings`.

Покрытие тестами:

- расчёт длительности посещения;
- подсчёт перестановок для малых списков;
- выбор более рейтингового места при ограниченном времени;
- жадное ранжирование для больших списков;
- предупреждение при некорректной длительности активности.

## Лабораторная работа 3

Задача участника 2: интеграция, подготовка тестовых сценариев, участие в end-to-end тестах.

Реализовано:

- Конфигурация интеграции через `planner.integration.*` в `application.properties`.
- `PlannerUpstreamClient` для HTTP-вызовов:
  - `location-context-service`: `POST /api/v1/context/analyze`;
  - `places-service`: `POST /api/v1/places/search`.
- Обогащение плана найденными местами из `places-service`.
- Защита от недоступности внешних сервисов: ошибка интеграции добавляется в `warnings`, а план строится по уже переданным местам.
- Тестовый сценарий `PlannerLab3ScenarioTest`: при `planner.integration.enabled=false` сервис не обращается наружу и возвращает предупреждение.
- Dockerfile для контейнеризации `planner-service`.

## Основной контракт API

### `POST /api/v1/plan/build`

Пример запроса:

```json
{
  "startTime": "10:00",
  "endTime": "14:00",
  "walkLocation": "Арбат, Москва",
  "walkPace": "MEDIUM",
  "discoverCategories": ["museum", "park"],
  "places": [
    {
      "placeId": "local_1",
      "name": "Локальное место",
      "category": "park",
      "latitude": 55.75,
      "longitude": 37.61,
      "estimatedHours": 1.0,
      "description": "",
      "rating": 4.2
    }
  ]
}
```

Пример ответа:

```json
{
  "items": [
    {
      "placeId": "local_1",
      "placeName": "Локальное место",
      "arrivalTime": "10:00",
      "departureTime": "11:00",
      "category": "park"
    }
  ],
  "totalPlaces": 1,
  "totalHours": 1.0,
  "warnings": [],
  "evaluatedOrderings": 1
}
```

## Запуск и проверка

Локальный запуск тестов:

```bash
cd planner-service
./gradlew test
```

Сборка Docker-образа:

```bash
cd planner-service
docker build -t travel-day-planner/planner-service .
docker run --rm -p 8083:8083 travel-day-planner/planner-service
```

Конфигурация по умолчанию:

```properties
server.port=8083
planner.integration.enabled=true
planner.integration.location-context-base-url=http://localhost:8081
planner.integration.places-base-url=http://localhost:8082
```
